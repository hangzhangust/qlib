# Qlib - Quantitative Investment Platform

## Development Commands

### Installation
```bash
make install          # Build Cython extensions + install in editable mode
make dev              # Build Cython extensions + install all optional deps
pip install -e .      # Editable install (requires Cython extensions already built)
make prerequisite     # Build Cython extensions only (rolling.pyx, expanding.pyx)
```

### Testing
```bash
cd tests && python -m pytest . -m "not slow" --durations=0   # Standard test suite
cd tests && python -m pytest . -m slow --durations=0          # Slow tests only
```
Tests require data: `python scripts/get_data.py qlib_data --name qlib_data_simple --target_dir ~/.qlib/qlib_data/cn_data --interval 1d --region cn`

### Linting (all via Makefile)
```bash
make black            # black . -l 120 --check --diff
make pylint           # pylint on qlib/ and scripts/
make flake8           # flake8 on qlib/
make mypy             # mypy on qlib/
make nbqa             # black + pylint on notebooks
make lint             # Run all linters
```

### Build & Docs
```bash
make build            # python -m build --wheel
make docs-gen         # sphinx build
```

### Running a Workflow
```bash
qrun examples/benchmarks/LightGBM/workflow_config_lightgbm_Alpha158.yaml
# or: python qlib/cli/run.py <config.yaml>
```

## Code Style
- Line length: 120 (enforced by black)
- Python 3.8+ compatible
- Formatting: black with `--exclude qlib/_version.py`
- Version is auto-generated by setuptools-scm into `qlib/_version.py` - do not edit

## Architecture

### Pipeline Flow
```
Config (C) → Data (D) → Model → Workflow/Recorder (R) → Backtest → Evaluation
```

### Global Singletons
- **`C`** (`qlib.config`) - Configuration dict: provider URIs, MLflow settings, paths
- **`D`** (`qlib.data`) - Data access: calendars, instruments, features, expressions
- **`R`** (`qlib.workflow`) - Experiment recorder: metrics, params, artifacts (MLflow backend)
- **`H`** - Cache manager

Bootstrap: `qlib.init()` loads config, mounts data providers, initializes recorder.

### Key Modules
| Module | Purpose |
|---|---|
| `qlib/data/` | Data providers (calendar, instruments, features), expression engine (`ops.py`), caching |
| `qlib/model/` | Abstract `Model` base class with `fit()`/`predict()` interface |
| `qlib/workflow/` | Experiment tracking via `Recorder` and `ExpManager` (MLflow) |
| `qlib/backtest/` | Portfolio simulation: `Exchange`, `Account`, `Order`, strategy execution |
| `qlib/contrib/` | Community implementations: models, strategies, data handlers (e.g. Alpha158), evaluation |
| `qlib/rl/` | RL trading agents: `Interpreter`, `Reward`, `Simulator` bridging RL ↔ backtest |
| `qlib/utils/` | Config parsing (`init_instance_by_config`), date helpers, data I/O, module loading |
| `qlib/config.py` | `QSettings` (pydantic-settings), `Config` class with attribute access |

### Design Patterns
- **Provider pattern**: Data access is abstracted through providers (`CalendarProvider`, `InstrumentProvider`, `FeatureProvider`, `ExpressionProvider`, `DatasetProvider`) swappable between local file and client-server modes
- **Config-driven instantiation**: `init_instance_by_config(config)` creates objects from YAML/dict configs with `class` and `kwargs` keys - used throughout for models, strategies, data handlers
- **Expression engine**: `qlib/data/ops.py` defines composable operators (e.g. `Ref`, `Mean`, `Std`) for feature engineering in a DSL
- **Cython extensions**: `qlib/data/_libs/rolling.pyx` and `expanding.pyx` provide fast windowed computations compiled via `make prerequisite`

### Entry Points
- **CLI**: `qrun` command (or `python qlib/cli/run.py`) runs full workflow from YAML config
- **Python API**: `qlib.init()` then use `D` for data, model classes for training, `backtest()` for simulation
- **Examples**: `examples/benchmarks/` has model configs; `examples/workflow_by_code.ipynb` for notebook usage
